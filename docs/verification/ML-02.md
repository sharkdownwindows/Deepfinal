# ML-02 Verification — Config-Driven Diffusers LoRA Wrapper

## Implemented

`scripts/train_run.py` validates one YAML config and launches the official
Diffusers `examples/dreambooth/train_dreambooth_lora.py` entry point through
Accelerate. The wrapper writes the resolved config, environment record, log,
status lifecycle, checkpoints, final adapter, and one adapter inference sample
under the configured run directory. It rejects duplicate outputs and records
errors as failed runs.

The official trainer path is supplied with `--diffusers-script` or the
`DIFFUSERS_TRAIN_DREAMBOOTH_LORA` environment variable. The wrapper does not
download or vendor third-party trainer code.

## Verification evidence

- Config validation and command argument mapping are covered by
  `tests/test_training_runner.py`.
- `tests/test_registry.py` covers lifecycle transitions and duplicate run
  protection.
- No real Diffusers training or adapter reload has been run here because the
  ML dependencies are absent and local GPU memory is limited. Adapter reload
  is performed by the wrapper after a successful training process and must be
  confirmed by a completed run artifact.

## Command

```bash
python scripts/train_run.py \
  --config configs/pilot/dog_plush_n10_r16_ts42.yaml \
  --diffusers-script third_party/diffusers/examples/dreambooth/train_dreambooth_lora.py
```
