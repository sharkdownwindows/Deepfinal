# BE-01 Verification — Config Validation and Run IDs

## Implemented

- Training YAML is validated for the Stable Diffusion v1.5 model ID and an
  immutable model commit revision.
- The run ID must match the concept, subset size, LoRA rank, and training seed.
- Training image count must equal the configured subset size.
- Rank, alpha, steps, resolution, batch size, accumulation, seed, and learning
  rate are checked before creating an artifact directory.
- `alpha == rank` is enforced.
- Existing output directories are rejected before a run starts; the registry
  also rejects duplicate run IDs, including completed runs.
- The full experiment validator accepts concept IDs containing underscores,
  such as `dog_plush`, and checks run ID concept and seed consistency.

## Verification evidence

Pure validation and CLI construction are covered by
`tests/test_training_runner.py`, `tests/test_be01.py`, and
`tests/test_config.py`. No model or GPU is needed for those checks.

## Limitations

The training run itself has not been executed in this environment. Runtime
evidence belongs to ML-01/ML-02 artifacts and must not be inferred from these
config checks.
