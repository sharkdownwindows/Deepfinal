# BE-02 Verification — Artifact Registry and Lifecycle

## Implemented

- Run status uses the `queued → running → completed|failed` lifecycle. Terminal
  states cannot be changed, and failures retain their error text.
- Status JSON is replaced atomically so an interrupted write does not leave a
  truncated lifecycle record.
- Each run stores environment metadata plus model revision, dataset concept and
  version, subset size, manifest path and SHA-256, and selected training
  parameters in `provenance.json`.
- Duplicate run IDs are rejected before an existing artifact can be replaced.

## Verification evidence

`tests/test_registry.py` covers lifecycle transitions, error persistence,
duplicate protection, provenance contents, and manifest-hash mismatch.
`tests/test_environment.py` covers the environment metadata contract.
